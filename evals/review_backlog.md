Study: per card in the deck, `eval --smooth --boss --next --v "up|upgrade=ID"` divided by its draw frequency; rank by gain per smith; check whether rest-vs-smith (`sts2-deckbuilding` section 6) should compare the rest against the summed debt rather than one upgrade.
- **RL curriculum design for the solver** (agreed with the user, 2026-10-06):
  - Everything in absolute HP; real starting HP with a 99-turn cap (no 999 HP: HP-conditional cards and relics need no special case).
  - Value head decomposed into outcomes: P(win), HP lost if won (distribution), potions used (per potion). The decision layer combines them with run-specific weights (win / loss stakes from the route, a price per potion from its value in the next boss fight); no reward weights baked into the network.
  - Difficulty is adaptive and used for SAMPLING only (prioritized replay of fights the solver wins 20-80 %), not in the reward.
  - Curriculum: start with easy fights, no potions, no extra relics, starter-like decks (a few cards added / removed / transformed, like Neow), high starting HP; then harder fights, potions up to 8, more relics, larger and more varied decks (upgrades, curses, colorless, other characters' cards, event cards), ancient relics. Keep a share of earlier stages (no forgetting); advance on fixed per-stage probe sets; report coverage (encounter x relic x potion x card type, and situation probes: lethal this turn, big-hit turn with a potion in hand, choice screens, multi-phase bosses).
  - Relics per act like a real run: Act 1 fights carry one Neow relic; Act 2 one Neow relic + one Act 2 ancient relic; Act 3 one Neow relic + one Act 2 and one Act 3 ancient relic. Handle relic kinds explicitly: macro-only relics (no combat effect) are ignored / masked out of the observation; relics that interact with potions (belt size, potion generation, potion effects) need potions in the scenario; relics tied to cards they add to the deck (and enchantments) must bring those cards. Needs a per-relic classification (combat / macro-only / potion-linked / card-linked).
  - Realistic setups (user): run the game's AutoSlay mode with god mode and random choices, and snapshot deck / relics / potions at each fight: the reachable distribution of real runs, a jump start between hand-made starter decks and random decks. It under-samples the long tail human players build on purpose (engines, heavy removal, synergy picks), so it complements, not replaces, the generated mix. (`decomp/MegaCrit.Sts2.Core.AutoSlay*`)
  - Prerequisites: observation and action space resized for up to 8 potions and more relics (retrain from scratch), the macro-only relic mask, fidelity checks for every content type before it enters training.

Normalise training by starting the player at a fixed large HP (e.g. 999) whatever the character, so the value is "HP lost in this fight" with no death truncation; the run-level worth of that loss (death at the real HP, the HP-worth curve) is applied outside the network at decision time.
